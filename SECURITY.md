# Security policy

**English** · [Español](#es)

## Supported versions

CodeSentry is a continuously deployed website. Security fixes target the current source on <code>main</code> and the live deployment produced from it. Older revisions are not maintained separately.

## Report a vulnerability privately

Use [GitHub private vulnerability reporting](https://github.com/Tykillita/CodeSentry/security/advisories/new) to contact the maintainers. Please do not publish vulnerability details in issues, pull requests, or discussions before coordinated disclosure.

Include the affected page, file, dependency, or commit; clear reproduction steps or a minimal proof of concept; the impact you observed; and any relevant browser or operating-system details. Do not include real credentials, private user data, or information belonging to other people. Avoid testing against systems or data you do not own.

Reports are reviewed on a best-effort basis; there is no guaranteed response or fix deadline. Coordinate any public disclosure with the maintainers and keep exploit details private until a disclosure date has been agreed.

# Política de seguridad

## Versiones con soporte

CodeSentry es un sitio web con publicación continua. Las correcciones de seguridad se aplican al código vigente en <code>main</code> y al despliegue live generado desde esa rama. Las revisiones anteriores no reciben mantenimiento por separado.

## Reportar una vulnerabilidad de forma privada

Usa el [canal privado de reportes de vulnerabilidad de GitHub](https://github.com/Tykillita/CodeSentry/security/advisories/new) para contactar a quienes mantienen el proyecto. No publiques detalles de la vulnerabilidad en issues, pull requests ni discusiones antes de coordinar su divulgación.

Incluye la página, archivo, dependencia o commit afectado; pasos claros para reproducir el problema o una prueba de concepto mínima; el impacto observado; y los datos pertinentes del navegador o sistema operativo. No incluyas credenciales reales, datos privados de usuarios ni información de otras personas. Evita probar sistemas o datos que no te pertenezcan.

Los reportes se revisan según disponibilidad; no se garantiza un plazo de respuesta ni de corrección. Coordina cualquier divulgación pública con quienes mantienen el proyecto y conserva privados los detalles de explotación hasta acordar una fecha para divulgarla.
